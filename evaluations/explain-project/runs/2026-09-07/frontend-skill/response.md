這個專案目前是很小的「待辦清單」前端原型：可以輸入待辦並顯示在頁面上，但目前的新增流程只更新瀏覽器記憶體，還沒有接上伺服器儲存。

整體只有一個頁面。`index.html` 提供輸入框、新增按鈕和清單，並載入 `app.js`；`app.js` 負責接收表單操作、保管當次開頁的待辦資料，以及更新畫面。另一個 `task-client.js` 已寫好呼叫 API 的函式，但頁面入口與 `app.js` 都沒有載入或呼叫它。[頁面入口](/private/tmp/explain-project-work-pf2duh5z/runs/frontend-skill/repo/index.html:6)

資料實際這樣走：

1. **開啟頁面**：程式先建立一個記憶體陣列，裡面有「試著新增一筆待辦」這筆範例，再把每筆標題顯示成清單項目。沒有向伺服器讀取既有待辦。
2. **按下新增**：程式攔住表單原本的送出動作，取得文字並去掉前後空白；如果只剩空字串就不新增。接著在瀏覽器產生 ID，將新待辦放進同一個陣列，重畫清單並清空表單。畫面上的新增結果直接來自這個陣列。[新增與顯示流程](/private/tmp/explain-project-work-pf2duh5z/runs/frontend-skill/repo/app.js:1)
3. **重新整理**：這個陣列會重新建立，因此剛新增的內容會消失，只留下原本的範例。程式沒有使用瀏覽器本機儲存，也沒有在這條操作路徑送出待辦資料。

目前最重要的未完成處，是「畫面新增」和「API 儲存」之間還沒接起來。`createTask(title)` 若被呼叫，會把標題以 JSON 送到 `/api/tasks`，檢查回應是否成功，再回傳伺服器的 JSON；但目前表單完全沒有走這條路，所以也沒有處理儲存中的狀態、儲存失敗提示，或把伺服器回傳的資料更新到清單。[尚未接入的 API 函式](/private/tmp/explain-project-work-pf2duh5z/runs/frontend-skill/repo/task-client.js:1)
