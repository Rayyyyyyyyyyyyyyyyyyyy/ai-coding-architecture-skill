這個專案讓使用者建立訂單，再查看通知處理結果。它由三個執行部分合作：瀏覽器提供表單與狀態畫面，Python API 負責建立、查詢訂單，另一支背景程式負責呼叫外部通知服務。API 與背景程式靠同一份 SQLite 資料庫交換工作，不是直接互相呼叫。

從建立訂單到通知完成，資料這樣走：

1. **填寫品項與信箱，按「建立」。** 瀏覽器把兩個欄位轉成 JSON，送到 `POST /orders`。API 確認必要欄位存在，再產生訂單 ID。
2. **先存訂單，再回覆已受理。** API 在同一個資料庫交易中新增一筆訂單與一筆通知工作，兩者狀態都是 `pending`。回覆 HTTP 202 與訂單資料，畫面顯示「等待通知」。這時只是訂單已建立，通知還沒送出。[建立與儲存程式](/private/tmp/explain-project-work-pf2duh5z/runs/background-skill/repo/store.py:25)
3. **背景程式取出待辦通知。** 每輪挑一筆 `pending` 工作，讀取對應訂單，把信箱與訂單 ID 傳到 `NOTIFY_URL` 指定的外部服務，並使用 `NOTIFY_TOKEN` 驗證。每輪結束後等一秒再繼續；不是保證每秒完成一筆。
4. **把通知結果寫回資料庫。** 外部服務回覆 HTTP 200，背景程式就將工作與訂單通知狀態一起改為 `sent`；呼叫途中發生例外則改為 `failed`。[通知呼叫與結果處理](/private/tmp/explain-project-work-pf2duh5z/runs/background-skill/repo/worker.py:9)
5. **畫面定時查詢結果。** 瀏覽器每秒呼叫 `GET /orders?id=...`，API 從資料庫取回目前狀態。畫面變成「通知已送出」或「通知失敗」後停止查詢；查詢出錯也會停止並顯示「無法取得最新狀態」。因此結果是靠畫面主動查詢取得，不是伺服器主動推送。[畫面資料往返](/private/tmp/explain-project-work-pf2duh5z/runs/background-skill/repo/index.html:17)

資料放在哪裡、由誰決定：

| 資料 | 存放與用途 |
|---|---|
| 訂單 ID、品項、信箱、通知狀態 | SQLite 的 `orders` 表，是 API 查詢及畫面顯示的依據。API 建立訂單，背景程式更新通知狀態。 |
| 等待處理的通知工作 | 同一資料庫的 `jobs` 表，存訂單 ID 與工作狀態；相當於一份簡單的待辦工作清單。 |
| 畫面正在追蹤哪筆訂單 | 瀏覽器此次頁面的記憶體。重新整理會失去追蹤中的 ID；資料庫中的訂單仍可保留，但目前沒有訂單列表或恢復追蹤的介面。 |
| 送到外部服務的內容 | 收件信箱與訂單 ID；這條通知請求沒有傳品項。外部服務如何保存或進一步處理，repo 沒有說明。 |

資料庫位置由 `ORDER_DB` 決定，預設是相對路徑 `orders.sqlite3`。兩支 Python 程式必須指向同一個實際檔案；若用預設值卻從不同目錄啟動，可能讀到不同資料庫。API 啟動時才會建立資料表，背景程式本身沒有初始化資料表。[資料庫設定與結構](/private/tmp/explain-project-work-pf2duh5z/runs/background-skill/repo/store.py:6)

目前程式已能串起「建立 → 排入工作 → 呼叫通知 → 寫回狀態 → 畫面查詢」的完整路徑，但有幾個界線要分清楚：

- **`sent` 只表示外部端點回覆 200。** 程式沒有確認收件者真正收到通知，也沒有處理後續送達回報；不能直接把它當作已送達。
- **失敗沒有自動重試。** 背景程式只挑 `pending`，改成 `failed` 就不再取出，也沒有保存失敗原因供畫面查看。缺少通知設定時，取到的工作同樣會被標成失敗。
- **沒有防止重複寄送的完整機制。** 取工作時沒有先標記「處理中」或獨占領取；若同時啟動多個背景程式，可能取到同一筆。若外部服務已接受通知、程式卻在寫回結果前中斷，也可能再次處理。
- **部署與外部服務仍無法確認。** repo 沒有憑證、部署紀錄或實際資料庫檔案，無法確認背景程式是否正在執行、兩個程序是否共用同一份資料庫、外部通知 API 是否可用，或其 200 回覆實際代表什麼。API 的程式入口目前監聽本機 `127.0.0.1:8080`。[啟動入口](/private/tmp/explain-project-work-pf2duh5z/runs/background-skill/repo/api.py:50)

以上是閱讀這份 repo 全部五個檔案後的靜態說明；沒有啟動服務、建立資料庫或發送通知，也沒有修改專案。程式的連接關係有依據，但實際端到端運作尚未在本次確認。
